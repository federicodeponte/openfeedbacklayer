## Gap (OPTION A)

### Buttons and checkbox render in Arial instead of the widget's `system-ui` stack

**Severity:** P1 polish miss (not a functional break, but contradicts the brief's typography criterion which is part of the 100 bar).

**Reproduction (`getComputedStyle` on the live URL):**

| Element | Computed `font-family` | Expected |
|---|---|---|
| `h3` "Send feedback" | `system-ui, -apple-system, sans-serif` | match |
| Textarea (message) | `system-ui, -apple-system, sans-serif` | match |
| Email `<input>` | `system-ui, -apple-system, sans-serif` | match |
| Subscribe `<label>` | `system-ui, -apple-system, sans-serif` | match |
| Hint `<p>` "Tip: Paste…" | `system-ui, -apple-system, sans-serif` | match |
| Close `<button>` (×) | **Arial** | should be system-ui |
| Screenshot `<button>` | **Arial** | should be system-ui |
| Send `<button>` | **Arial** | should be system-ui |
| Retry `<button>` (error state) | **Arial** | should be system-ui |
| Close `<button>` (success/error state) | **Arial** | should be system-ui |
| Remove-screenshot `<button>` (×) | **Arial** | should be system-ui |
| Subscribe `<input type=checkbox>` | **Arial** | should be system-ui |

Verified by `getComputedStyle(el).fontFamily` on Chrome 145 (Linux). The widget container at `src/components/FeedbackWidget.tsx:284` sets `fontFamily: 'system-ui, -apple-system, sans-serif'` on the FAB wrapper. The textarea and email input styles include `fontFamily: 'inherit'` (lines 363 and 373) which correctly resolve. The button and checkbox styles (`actionButton`, `closeButton`, `removeButton`, `checkbox`) do not set `fontFamily`, so the UA stylesheet's button reset wins and Chromium falls back to **Arial**.

Screenshot evidence: `docs/launch-readiness/agent-runs/screenshots-r4/10-typography-buttons-arial.png` (Send / 📷 Screenshot / × buttons visually thinner than the body type on Linux; difference is more pronounced on macOS where the rest renders in San Francisco).

**Why it's a real launch blocker (not stylistic preference):**
- The brief's step 12 explicitly checks for typography consistency.
- Mixed Arial + system-ui within the same widget is a measurable, browser-deterministic mismatch (not a taste call) — `getComputedStyle` reports two different stacks.
- On macOS (the most common host platform for the developers Federico is shipping this to) SF vs Arial is visually obvious in the same dialog.
- This is the well-known UA button-font reset and the fix is canonical: every styled control gets `fontFamily: 'inherit'`.

**Fix (4 properties added, ~30s edit):**

```diff
 closeButton: {
+    fontFamily: 'inherit',
     background: 'none',
     ...
 },
 removeButton: {
+    fontFamily: 'inherit',
     position: 'absolute' as const,
     ...
 },
 actionButton: {
+    fontFamily: 'inherit',
     flex: 1,
     ...
 },
 checkbox: {
+    fontFamily: 'inherit',
     width: 14,
     ...
 },
```

After the patch, `npm run build` and reload — every control will resolve to the same `system-ui, -apple-system, sans-serif` stack as the rest of the widget. Verification command: `getComputedStyle(document.querySelector('button[aria-label="Feedback"] ~ * button')).fontFamily` should return `"system-ui, -apple-system, sans-serif"` for all six button instances.
