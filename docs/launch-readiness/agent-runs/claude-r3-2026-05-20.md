## Evidence

### 1. Email input — autocomplete

```json
{
  "found": true,
  "autocompleteProperty": "email",
  "autocompleteAttribute": "email",
  "name": "email",
  "ariaLabel": "Your email (optional, to hear back)"
}
```

Both the DOM property and the HTML attribute resolve to `email`. Password managers and browser autofill will now correctly populate this field. Aria-label present for screen readers.

### 2. Close button — WCAG-AAA touch target

```json
{
  "found": true,
  "width": 44,
  "height": 44,
  "ariaLabel": "Close feedback",
  "padding": "10px",
  "passesAAA": true
}
```

Exact 44x44 measured rect, padding 10px confirms the bump landed. Passes WCAG 2.1 AAA (2.5.5 Target Size, 44x44 CSS pixels minimum).

### 3. Screenshot remove button — only renders after a screenshot is attached

Reproduction: synthesized a 100x100 PNG client-side and dispatched a `paste` ClipboardEvent on the textarea carrying the File via DataTransfer. The widget accepted the paste and rendered the screenshot preview with the remove button.

Preview confirmed before measurement:

```json
{
  "imgsCount": 1,
  "previews": [{ "src": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAAAGQA", "alt": "Screenshot" }],
  "removeBtnFound": true,
  "removeBtnAria": "Remove screenshot"
}
```

Then measured:

```json
{
  "found": true,
  "ariaLabel": "Remove screenshot",
  "width": 44,
  "height": 44,
  "padding": "1px 6px",
  "text": "×",
  "passesAAA": true
}
```

Note on padding: the visible glyph is the small `×` but the button bounding rect is enforced to 44x44 (likely via `width`/`height` rather than padding), which still satisfies AAA target-size since 2.5.5 measures the activation area regardless of inner glyph size.
